> 最后更新：2026-09-24（§五 界面改版）
> 模块：core

## 一、产品类型判断与原型策略

foreman 是**混合型**产品，M1 的交付物有三类：

| 交付物 | 类型 | 原型形式 | 设计文档 |
|--------|------|---------|---------|
| 面板与 IM（主控制面） | Web 应用 | HTML 可交互页面 | 本文档 |
| worker 与 CLI（runtime 接入、斜杠命令兜底） | CLI 工具 | 终端交互模拟 | `core-03-runtime-cli-design.md` |
| 飞书机器人、调度员会话、线程介入 | 对话式产品 | 对话流程脚本 | `core-04-conversation-design.md` |

**场景粒度检查**：Phase 1 的 12 个场景都是完整业务路径，无 CRUD 拆分，无需回退。

**设计系统**（ui-ux-pro-max 检索 `developer productivity dashboard chat workspace agent orchestration technical dark`）：

- 配色：背景 `#0F172A`，面板 `#1E293B`，次级 `#334155`，行动色 `#22C55E`（"代码深色 + 运行绿"），正文 `#F8FAFC`。补充语义色：待拍板 `#F59E0B`，失败 `#EF4444`，信息 `#38BDF8`。
- 字体：正文 Fira Sans，编号、日志、命令 Fira Code。
- 检索给出的"横向滚动落地页"模式面向营销页，对控制台类产品不适用，**不采用**；采用其配色、字体、动效时长（150–300ms）和交付前检查清单（SVG 图标、hover、焦点态、reduced-motion、响应式断点）。
- 面板以桌面 1440px 为主设计宽度，1024px 收起右栏，768px 以下只保留收件箱与线程视图（手机端拍板走飞书，不做移动端完整布局）。

## 二、信息架构

### 2.1 导航与路由

```
/                         → 重定向到 /inbox
/inbox                    收件箱：所有待我处理的项（审批、需要输入、失败三选一、候选）
/c/:channel               频道：消息流，线程列表
/c/:channel/t/:taskId     线程：一个根任务的全部消息、子任务、事件、产物
/runtimes                 状态视图：runtime、会话、来源健康度
/trust                    信任视图：动作类型 × 计数 × 状态，升降级记录
/settings                 设置：来源默认频道、路由默认值、agent 并发、飞书表情、Jira 映射
```

### 2.2 页面布局（Slack 式三栏）

```
┌──────────┬──────────────────────────────────┬──────────────────┐
│ 左栏 240 │ 中栏 自适应                        │ 右栏 360（可收起）│
│          │                                  │                  │
│ 收件箱 3 │ 频道消息流 / 线程消息流             │ 任务详情：       │
│ ──────── │                                  │  上下文包         │
│ 频道     │  [消息][摘要卡][审批卡][草案卡]      │  任务树           │
│  # jira  │  ...                             │  会话与 runtime   │
│  # feishu│                                  │  产物             │
│  # doris-│ ┌──────────────────────────────┐ │  信任状态         │
│    index │ │ 输入框：口语 / 斜杠命令        │ │                  │
│ ──────── │ └──────────────────────────────┘ │                  │
│ 状态 ●   │                                  │                  │
│ 信任     │                                  │                  │
│ 设置     │                                  │                  │
└──────────┴──────────────────────────────────┴──────────────────┘
```

- 左栏：收件箱（带未处理计数）、频道列表（用户自建，来源默认频道 `#jira`、`#feishu` 在首次入库时自动创建并可改名）、状态（带在线 runtime 圆点）、信任、设置。
- 中栏：频道或线程的消息流。消息类型见 2.4。底部输入框接受口语和斜杠命令。
- 右栏：当前线程所属任务的详情；在频道视图下显示频道概况（进行中任务数、待拍板数）。

### 2.3 核心对象与标识

| 对象 | 标识 | 展示 |
|------|------|------|
| 任务 | `T-<自增>` | 线程标题：`T-231 · CIR-20001 · 查询超时回归` |
| 子任务 | `T-231.1` | 任务树节点，类型：PR / 分支 / review |
| 审批 | `A-<自增>` | 审批卡右上角，飞书消息首行 |
| 会话 | runtime 名 + agent + 短 ID | `dev · claude · 7de71d` |
| runtime | 用户命名 | `dev`、`center`、`laptop` |

### 2.4 消息类型（线程内）

| 类型 | 来源 | 外观 | 可操作 |
|------|------|------|--------|
| 系统事件 | 平台 | 灰色单行，带时间 | 无 |
| 分流卡 | agent | 卡片：档位、工作量、目标仓库、建议路径、代码定位摘要 | 改档位 / 改仓库 / 改 runtime / 按建议执行 / 否决 |
| 进展摘要 | agent（MCP 回写） | 气泡，≤200 字，右下"展开日志" | 展开日志 |
| 需要输入 | agent | 黄色边框气泡，问题正文 | 输入框聚焦，回复即送入会话 |
| 审批卡 | 平台 | 卡片：动作类型、正文、信任计数 n/5 | 确认 / 修改后确认 / 否决 |
| 产物卡 | agent | 卡片：PR 链接、方案文档、demo 分支 | 打开 / 按方案实现 |
| 失败卡 | 平台 | 红色边框：原因摘要、日志入口 | 重试 / 换 agent / 放弃 |
| 草案卡 | 调度员 | 卡片：解析出的任务字段 | 创建 / 修改 / 取消 |
| 用户消息 | 我 | 右对齐气泡 | 无 |

### 2.5 任务状态机

```
draft ──创建──▶ triaging ──分流卡就绪──▶ pending_decision ──拍板──▶ queued ──runtime 就绪──▶ running
                                                                         │                      │
                                                                         │                      ├─需要输入─▶ waiting_input ─回复─▶ running
                                                                         │                      ├─失败─────▶ failed ─重试/换 agent─▶ queued
                                                                         │                      └─完成─────▶ delivered ─子任务全完成且闭环─▶ done
                                                                         └─runtime 离线────────▶ queued（显示等待原因）
任意状态 ─用户暂停─▶ paused ─恢复─▶ 原状态
```

M1 中 `delivered → done` 的闭环动作只有"产物摘要镜像回来源"（Jira 评论 / 飞书回帖）；合入与 Jira 流转属 M2。

## 三、逐场景交互规格

### S01: Jira 单自动入库并生成分流卡 — 面板侧

**涉及视图**：收件箱、`#jira` 频道、线程、右栏任务详情

**交互流程**：
1. 平台创建任务 → `#jira` 频道出现一条新线程 `T-231 · CIR-20001 · <summary>`，线程首条为系统事件"来自 Jira，assignee 变更为我"。
2. 上下文包组装完成 → 右栏"上下文包"区块可展开：需求原文、Jira 字段（项目、组件、版本、优先级）、评论摘要、附件清单、目标仓库（来源标注：映射 / LLM 猜测 / 手动）。
3. 预跑代码定位 → 线程出现系统事件"代码定位：dev · claude · 运行中"，完成后分流卡出现。
4. 分流卡同时进入收件箱（类型：待拍板），左栏收件箱计数 +1。
5. 降级：开发机离线时分流卡以"无代码定位"形式出现，卡片顶部黄条"开发机离线，代码定位待补"；恢复后卡片原位更新并在线程追加系统事件。

**分流卡字段**：

| 字段 | 取值 | 可编辑 |
|------|------|--------|
| 档位 | 简单修复 / 出方案 / 出原型 | 是（下拉） |
| 工作量预估 | 小（<2h）/ 中（半天）/ 大（>1 天） | 否 |
| 目标仓库 | 仓库名 + 来源标注 | 是（下拉，候选来自 runtime 标签） |
| 建议路径 | 一句话 | 否 |
| 代码定位 | 文件与函数清单，最多 8 条，可展开 | 否 |
| runtime | 默认按路由规则 | 是（下拉，只列在线且标签匹配的） |
| agent | 默认按轮换 | 是 |

#### 验收条件（交互级）

##### 正常：分流卡出现在两个位置
- **GIVEN** 面板打开在 `/inbox`，`#jira` 频道存在
- **WHEN** 平台完成 CIR-20001 的分流卡
- **THEN** 收件箱顶部插入一张"待拍板"条目（无刷新，WebSocket 推送），左栏收件箱计数 +1，`#jira` 频道列表中 `T-231` 线程带未读标记

##### 正常：目标仓库待确认的卡片
- **GIVEN** 分流卡目标仓库为"待确认"
- **WHEN** 我在收件箱打开该卡
- **THEN** 仓库下拉高亮为黄色并预选 LLM 候选第一项，"按建议执行"按钮禁用直到我选定仓库

##### 异常：开发机离线时的卡片更新
- **GIVEN** 分流卡以降级形式显示
- **WHEN** 开发机恢复且补跑完成
- **THEN** 卡片黄条消失，代码定位区块出现，收件箱条目位置不变，线程追加"代码定位已补齐"事件

### S03: 拍板分流路径并一键启动 agent — 面板侧

拆分为两个子场景：**S03.1 拍板**（收件箱或线程内的分流卡操作）与 **S03.2 启动与产物**（线程内的会话生命周期展示）。

#### S03.1 拍板

**交互流程**：
1. 收件箱条目点开 → 右侧抽屉显示分流卡全文 + 上下文包摘要（或直接在线程内操作，两处同一张卡）。
2. 可改：档位、目标仓库、runtime、agent。改动即时保存为"我的覆盖"，卡片显示"已修改"标记。
3. 点"按建议执行"（未修改）或"按修改执行"（有修改）→ 按钮 loading → 任务状态 `queued` → 收件箱条目消失，线程出现系统事件"已拍板：路径=简单修复，runtime=dev，agent=codex（轮换）"。
4. 点"否决" → 弹出单行原因输入（可空）→ 任务状态 `paused`，线程记录否决原因；否决不计入信任计数（分流卡确认的否决只影响该任务）。
5. 飞书侧同一审批用 ✅ 表情等价于"按建议执行"（见 core-04）。

**快捷键**：收件箱内 `j/k` 上下，`Enter` 打开，`a` 按建议执行，`x` 否决，`e` 展开修改。

##### 验收条件（交互级）

###### 正常：未修改直接执行
- **GIVEN** 收件箱第一条为 T-231 的分流卡，我未修改任何字段
- **WHEN** 我按 `a`
- **THEN** 条目在 300ms 内滑出收件箱，`#jira` 频道 T-231 线程新增系统事件"已拍板（原样确认）"，"分流卡确认"动作类型计数 +1

###### 正常：修改后执行
- **GIVEN** 我把 runtime 从 `dev` 改为 `laptop`
- **WHEN** 我点"按修改执行"
- **THEN** 系统事件写明"runtime=laptop（手动覆盖）"，"分流卡确认"计数不变

###### 异常：runtime 下拉无可用项
- **GIVEN** 任务需要 `build:doris` 标签，开发机离线
- **WHEN** 我打开 runtime 下拉
- **THEN** 下拉只显示"dev（离线）"且不可选，按钮文案变为"执行（等待 dev 上线）"，点击后任务进入 `queued` 并在线程显示等待原因

#### S03.2 启动与产物

**交互流程**：
1. `queued → running`：线程出现系统事件"会话已启动 dev · codex · 3f2a1c"，右栏"会话与 runtime"区块显示 worktree 路径、启动时间、状态徽标（运行中为绿色脉冲）。
2. agent 通过 MCP 回写进展 → 线程追加进展摘要气泡，右栏不变。
3. 完成 → 产物卡：简单修复显示 PR 链接与 diff 统计；出方案显示方案 markdown 折叠预览与"按方案实现"按钮；出原型显示 demo 分支名与说明链接。
4. 产物摘要镜像回来源 → 系统事件"已镜像到 Jira 评论 #12345"（该动作受信任升级：初期生成审批卡）。
5. 失败 → 失败卡三选一；`重试` 沿用同一 agent 与 worktree；`换 agent` 切到另一家并保留 worktree；`放弃` 任务进入 `paused`。
6. 交叉 review：实现完成后自动创建子任务 `T-231.2 review`，线程显示"review 由 claude 执行（作者 codex）"。

##### 验收条件（交互级）

###### 正常：从启动到 PR
- **GIVEN** T-231 已拍板为简单修复
- **WHEN** 会话完成并创建 PR
- **THEN** 线程依次出现"会话已启动"、≥1 条进展摘要、产物卡（含 PR 链接）、子任务 `T-231.1 PR` 出现在右栏任务树，状态 `delivered`

###### 正常：按方案实现
- **GIVEN** 产物卡为方案
- **WHEN** 我点"按方案实现"
- **THEN** 不弹分流卡，直接以"简单修复"路径、同一 runtime 创建实现会话，方案全文作为上下文包附加项

###### 异常：并发已满的排队展示
- **GIVEN** dev 上 codex 已有 3 个运行中会话
- **WHEN** T-231 拍板为 codex
- **THEN** 线程显示"排队：codex 队列第 2 位"，右栏会话区块显示灰色"排队中"；若任务类型为分析类且 claude 有空位，则显示"已改派 claude（codex 满）"

### S04: 在 IM 频道用口语派活 — 面板侧

**涉及视图**：频道消息流、输入框、草案卡

**交互流程**：
1. 左栏"+ 新建频道"→ 输入名称（小写、连字符）→ 创建后进入空频道，顶部提示"在这里用一句话派活，或输入 `/` 查看命令"。
2. 输入框：普通文本回车发送；以 `/` 开头弹出命令面板（`/task new`、`/task pick`、`/task pause`、`/task resume`、`/runtime`、`/approve`）；`Shift+Enter` 换行。
3. 发送口语 → 频道出现我的消息 → 系统事件"调度员会话拉起中"（首次或回收后）→ 草案卡出现（≤30 秒）。
4. 草案卡字段：需求来源（可点开）、目标仓库、路径、pick 目标（M1 只记录不执行）、runtime、agent。可修改。
5. 点"创建"→ 频道出现新线程入口，任务进入 `triaging`，之后同 S01 步骤 2 起。
6. 澄清：调度员无法确定时，草案卡位置换为"澄清问题"气泡，列出候选（最近任务 / Jira 单），点候选即补全。
7. 多任务：一句话对应多个任务时并排出现多张草案卡，各自独立创建。
8. 斜杠命令兜底：`/task new --source CIR-19418 --repo selectdb-core --path fix` 直接产出草案卡，不经调度员；输入框在调度员不可用时顶部显示灰条"调度员不可用，可用斜杠命令"。

##### 验收条件（交互级）

###### 正常：一句话到草案卡
- **GIVEN** 频道 `#doris-index` 已存在且调度员会话已回收
- **WHEN** 我输入"把 CIR-19418 修了，顺便 pick 到 branch-selectdb-doris-3.1"并回车
- **THEN** 频道先出现"调度员会话拉起中"，30 秒内出现草案卡：来源 CIR-19418、仓库 selectdb-core、路径 简单修复、pick 目标 branch-selectdb-doris-3.1（标注"M2 执行"）；"创建"按钮可用

###### 正常：命令面板
- **GIVEN** 输入框为空
- **WHEN** 我输入 `/`
- **THEN** 输入框上方弹出命令列表，方向键选择，`Tab` 补全参数模板

###### 异常：澄清
- **GIVEN** 我输入"看看那个索引的问题"
- **WHEN** 调度员返回澄清
- **THEN** 频道出现澄清气泡与最多 5 个候选按钮，不出现草案卡；点候选后草案卡出现并预填

### S06: 审批双通道与信任升级 — 面板侧

拆分为 **S06.1 审批卡** 与 **S06.2 信任视图**。

#### S06.1 审批卡

**出现位置**：收件箱（类型：审批）与对应线程，同一张卡。

**卡片结构**：
- 头部：`A-88 · 回复 review 意见 · 信任 2/5`，右侧通道状态"飞书已推送"
- 正文：动作的完整内容（如回复草稿全文、要重跑的 CI 配置名）
- 底部：`确认` `修改后确认` `否决`；`修改后确认`展开可编辑正文，保存后按钮文案变为"按修改确认（不计数）"

**行为**：
- 任一通道处理后，另一通道 5 秒内失效：面板卡片变灰并标"已在飞书批准 · 12:03"。
- 正文被 agent 变更 → 卡片顶部红条"内容已变更，原审批作废"，下方出现新审批卡，旧卡折叠。
- 达到自动阈值后的动作不生成审批卡，线程出现系统事件"自动执行（重跑 CI，信任 5/5）"，事件右侧有"否决并回滚"链接，7 天内可点。

##### 验收条件（交互级）

###### 正常：面板确认
- **GIVEN** 收件箱有 A-88
- **WHEN** 我点"确认"
- **THEN** 卡片 300ms 内变为"已确认 · 面板"，收件箱条目移除，线程内同一卡片同步更新，信任计数显示 3/5

###### 正常：飞书先批
- **GIVEN** A-88 同时在面板与飞书
- **WHEN** 飞书 ✅ 事件到达
- **THEN** 面板卡片变灰标"已在飞书批准"，按钮禁用

###### 异常：修改后确认不计数
- **GIVEN** A-88 信任 2/5
- **WHEN** 我修改正文后确认
- **THEN** 动作按新正文执行，卡片显示"已确认（修改，不计数）"，信任仍为 2/5

###### 异常：事后否决
- **GIVEN** 一条自动执行的"回复 review 意见"
- **WHEN** 我点"否决并回滚"
- **THEN** 弹出确认框说明"将撤回回复并将该动作类型降级为人工"，确认后线程记录降级事件，信任视图该类型计数归零

#### S06.2 信任视图（`/trust`）

**表格列**：动作类型、当前状态（人工 / 自动 / 锁定人工）、连续原样确认数 n/5、最近一次否决时间、7 天内自动执行次数、操作（手动重置为人工）。

### S07: 跟踪会话进展并在线程中介入 — 面板侧

**涉及视图**：线程、右栏会话区块、收件箱（需要输入类型）

**交互流程**：
1. 进展摘要气泡：时间、agent 标识、≤200 字摘要；右下"展开日志"→ 气泡下方内嵌等宽日志面板（该摘要时间段的原始输出，最多 400 行，可"查看完整日志"跳到全屏日志页 `/c/:channel/t/:taskId/logs/:sessionId`）。
2. 需要输入：黄色边框气泡 + 收件箱出现"需要输入"条目 + 飞书推送。输入框 placeholder 变为"回复 codex 的问题…"，发送后气泡下出现"已送入会话 · 12:05"，任务状态回到 `running`。
3. 完成：完成摘要气泡 + 产物卡，右栏会话状态变为"已完成（进程将在 1 小时后停止）"。
4. 会话已停止后追加消息：发送后系统事件"恢复会话 3f2a1c…"，随后正常。
5. runtime 离线时追加：输入框上方灰条"dev 离线，消息将在上线后送入"，消息气泡带"排队"标记。
6. 手动干预：右栏会话区块有"停止会话"按钮（二次确认），停止后任务 `paused`。

##### 验收条件（交互级）

###### 正常：展开日志
- **GIVEN** 线程有一条进展摘要
- **WHEN** 我点"展开日志"
- **THEN** 200ms 内摘要下方展开日志面板，首行显示该时间段范围，末行有"查看完整日志"链接

###### 正常：回复需要输入
- **GIVEN** 线程最后一条为"需要输入：用方案一还是方案二？"
- **WHEN** 我输入"方案二"回车
- **THEN** 我的消息出现，10 秒内其下出现"已送入会话"，收件箱"需要输入"条目移除，右栏状态回到"运行中"

###### 异常：离线排队
- **GIVEN** dev 离线
- **WHEN** 我在线程追加消息
- **THEN** 消息带"排队"标记，输入框上方灰条出现；dev 上线后标记变为"已送入会话"

## 四、全局交互约定

- 所有推送通过 WebSocket，无需刷新；断线时顶部出现细红条"连接中…"，恢复后自动同步。
- 所有卡片操作按钮在请求期间 loading 并禁用，失败时按钮下方红字提示且可重试。
- 时间显示相对时间（"3 分钟前"），hover 显示绝对时间。
- 空状态文案：收件箱空为"没有需要你处理的事"，频道空为"用一句话派活，或输入 / 查看命令"。
- 键盘：全局 `g i` 收件箱、`g r` 状态、`g t` 信任；线程内 `Esc` 收起右栏。
- 无 emoji 图标，使用 Lucide 风格内联 SVG；深色为默认，跟随系统可切浅色（§五）。

平台行为问题（同批修复，非纯界面）：

- PR 被否决后 agent 停下，会话结束，任务却被标成「已交付」。改为：会话结束且没有产物 → 任务暂停，收件箱出现「需要处理」，在线程里回复即在原会话继续。
- 暂停后点「恢复」只改状态不拉起会话，任务空转。改为：恢复到运行态且没有活会话时，续接原会话。
- 拍板改了仓库，路由不看 runtime 是否登记该仓库。改为：代码任务只派给登记了该仓库的 runtime；都没有时进收件箱说明原因。

### 5.2 视觉规范

- 主题：深色默认，跟随系统，可在左栏底部切换（选择只存在本机浏览器）。颜色全部走 CSS 变量，深浅两套。
