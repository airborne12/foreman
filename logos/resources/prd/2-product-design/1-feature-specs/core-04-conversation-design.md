## 一、产品类型与原型策略

这一部分是**对话式产品**：用户通过飞书消息、表情和 IM 频道里的自然语言与平台交互，平台背后由调度员会话（订阅 CLI）和固定规则响应。原型形式为对话流程脚本。

三个对话主体：

| 主体 | 身份 | 出现位置 | 由什么驱动 |
|------|------|---------|-----------|
| 平台机器人 | 飞书应用 `cli_a94d…` 的机器人身份 | 飞书私聊、群 | 固定规则，不用 LLM |
| 调度员 | 每个 IM 频道一个按需拉起的 agent 会话 | 面板频道 | Claude 或 Codex 订阅 CLI，通过 MCP 调平台接口 |
| 任务会话 | 每个任务的工作会话 | 面板线程 | 同上 |

## 二、飞书侧协议

### 2.1 表情协议

| 表情 | 对象 | 含义 | 谁的表情有效 |
|------|------|------|-------------|
| 📌 PUSHPIN | 任意消息 | 入库为任务 | 仅 owner_open_id |
| ✅ DONE | 机器人发出的审批消息 | 确认（等价面板"确认"） | 仅 owner_open_id |
| ❌ CrossMark | 机器人发出的审批消息 | 否决 | 仅 owner_open_id |
| 👀 Eyes | 机器人发出的任何消息 | 无动作，仅供自己标记 | 忽略 |

规则：
- 表情事件通过机器人身份的 WebSocket 订阅接收，`operator_type` 非 user 或 open_id 不匹配一律忽略。
- 同一消息上先 ✅ 后 ❌：以第一个有效表情为准，后者忽略并回一条"A-88 已于 12:03 确认，如需撤销请到面板"。
- 审批消息的正文哈希与审批绑定，正文变更后旧消息被机器人回复"已作废"并发新消息。

### 2.2 机器人消息模板

**入库确认（回复在原消息下）**：
```
已收录为 T-231 · 目标仓库待定 · 面板：<链接>
```

**待拍板推送（私聊）**：
```
[待拍板] A-87 · 分流卡 · T-231 · CIR-20001 查询超时回归
档位 简单修复 · 预估 小 · 仓库 selectdb-core（映射）· runtime dev · agent codex
建议：定位到 be/src/olap/rowset/segment_v2/inverted_index_reader.cpp，改 timeout 传递
✅ 按建议执行   ❌ 否决   面板修改：<链接>
```

**审批推送（私聊）**：
```
[审批] A-88 · 回复 review 意见 · T-231.1 apache/doris#67657 · 信任 2/5
> （回复草稿全文，最多 800 字，超出截断并给链接）
✅ 确认   ❌ 否决   修改后确认请到面板
```

**需要输入（私聊）**：
```
[需要你回答] T-231 · codex：
> 方案一保留旧接口做兼容，方案二直接删除。选哪个？
在面板线程回复，或直接回复本消息
```
用户直接回复该私聊消息（飞书"回复"）→ 视为线程回复，送入会话。

**降级与告警（私聊）**：
```
[告警] dev 离线 5 分钟（隧道无法重建）· 3 个任务等待中 · 面板：<链接>
```

**每日摘要**：M3 范围，M1 不发。

### 2.3 @机器人派活（群）

- 触发：群消息文本含 @机器人。
- 有引用消息：被引用消息为需求原文，@ 的那句为补充说明。
- 无引用：@ 的那句本身为需求原文，前后 20 条为上下文。
- 机器人回复同"入库确认"模板。
- 群里其他人 @机器人：忽略，不回复（M1 单用户）。

## 三、逐场景对话规格

### S02: 飞书消息显式入库

**对话流程**：
1. 我在群里给同事消息加 📌。
2. 机器人（≤5 秒）在该消息下回复入库确认。
3. 平台组装上下文包：原消息、前后各 20 条、群名、发送者；LLM 猜目标仓库。
4. 预跑代码定位（dev），分流卡就绪 → 私聊推送"待拍板"。
5. 我在私聊 ✅ 或去面板。

**AI 行为规范（目标仓库猜测）**：
- 输入：原消息与上下文；输出：仓库候选（最多 3 个）与置信度；置信度 <0.6 时标"待确认"。
- 只从 runtime 标签里已登记的仓库中选，不编造仓库。

#### 验收条件（交互级）

##### 正常：表情入库到推送
- **GIVEN** 机器人在群内，我为 owner
- **WHEN** 我给一条消息加 📌
- **THEN** 5 秒内原消息下出现"已收录为 T-232…"，10 分钟内私聊收到"[待拍板] A-89…"消息

##### 异常：他人表情
- **GIVEN** 同上
- **WHEN** 同事加 📌
- **THEN** 无任何回复，平台日志记一条 ignored 事件

##### 异常：机器人不在群
- **GIVEN** 我在一个机器人未加入的群加 📌
- **WHEN** 事件无法送达
- **THEN** 无回复；面板设置页"飞书"区块显示提示"机器人需加入群才能收到表情事件"

### S04: 调度员解析口语

**对话流程**（在面板频道内）：
1. 我发一句话。
2. 平台检查该频道是否有活跃调度员会话；无则以 `claude --bg` 或 `codex exec` 拉起，系统提示词包含：频道名、最近 50 条频道消息、可用 runtime 与标签、可用仓库、MCP 工具清单（`lookup_jira`、`lookup_pr`、`list_tasks`、`propose_task`、`ask_clarification`）。
3. 调度员用工具查证引用（Jira 单、PR 号），调用 `propose_task` 产出草案（可多张）或 `ask_clarification`。
4. 平台把草案渲染为草案卡；我"创建 / 修改 / 取消"。
5. 会话空闲 30 分钟回收；再次拉起时用频道历史重建上下文。

**AI 行为规范**：
- 只提出草案，不直接创建任务；创建永远由用户点按钮。
- 引用的 Jira 单或 PR 必须查证存在，查不到就澄清，不猜。
- 一句话含多个独立需求时拆成多张草案。
- 澄清最多一轮；用户回答后必须给出草案或明确说无法处理。
- pick 目标在 M1 只记录进草案字段，不触发执行，卡片上标注"M2 执行"。
- 不在频道里长篇解释，草案卡即回复；需要说明时一句话。

#### 验收条件（交互级）

##### 正常：查证后出草案
- **GIVEN** CIR-19418 存在
- **WHEN** 我说"把 CIR-19418 修了，顺便 pick 到 branch-selectdb-doris-3.1"
- **THEN** 调度员调用 `lookup_jira("CIR-19418")` 后调用 `propose_task`，频道出现一张草案卡，字段齐全

##### 正常：多任务
- **WHEN** 我说"CIR-19418 和 CIR-19420 都修一下"
- **THEN** 两次 `lookup_jira`、两次 `propose_task`，两张草案卡并排

##### 异常：引用不存在
- **WHEN** 我说"把 CIR-99999 修了"
- **THEN** `lookup_jira` 返回 not found，调度员调用 `ask_clarification("没找到 CIR-99999，是这几个吗？")` 并附最近分配给我的 5 个单作为候选

##### 异常：调度员不可用
- **GIVEN** claude 与 codex 额度都耗尽
- **WHEN** 我发口语
- **THEN** 频道出现系统提示"调度员不可用（额度），可用 /task new …"，我的消息保留，额度恢复后不自动重放

### S06: 飞书表情审批

**对话流程**：
1. 平台生成审批 → 私聊推送审批消息（模板 2.2）。
2. 我 ✅ → 机器人回复"A-88 已确认（信任 3/5），正在执行" → 执行完成后再回复"A-88 已完成：<结果一句话>"。
3. 我 ❌ → 机器人回复"A-88 已否决，该类型信任计数已清零" → 面板同步。
4. 面板先处理 → 机器人在原消息下回复"A-88 已在面板确认"。
5. 正文变更 → 原消息下回复"A-88 内容已变更，本条作废"，新消息推送。

#### 验收条件（交互级）

##### 正常：✅ 确认
- **GIVEN** 私聊收到 A-88
- **WHEN** 我加 ✅
- **THEN** 5 秒内收到"已确认（信任 3/5）"，面板卡片变灰

##### 异常：先 ✅ 后 ❌
- **GIVEN** A-88 已被 ✅
- **WHEN** 我再加 ❌
- **THEN** 收到"A-88 已于 12:03 确认，如需撤销请到面板"，不执行否决

##### 异常：对已作废消息表情
- **GIVEN** A-88 的旧消息已标作废
- **WHEN** 我在旧消息上 ✅
- **THEN** 收到"本条已作废，请对新消息操作"

### S07: 线程介入与飞书回复

**对话流程**：
1. 会话 `agent_needs_input` → 线程黄色气泡 + 私聊推送"需要你回答"。
2. 我在线程回复，或直接在飞书回复该私聊消息。
3. 平台以"追加消息"送入会话（`--bg --resume <id>` / `codex exec resume <id>`）。
4. 会话继续；下一条进展摘要回到线程；飞书不再推送除非再次需要输入。

**AI 行为规范（任务会话）**：
- 会话必须通过 MCP `report_progress` 每完成一个可感知步骤回写 ≤200 字摘要；连续 10 分钟无回写，平台在线程标"无进展 10 分钟"。
- 需要用户决策时调用 `ask_user`，而不是在输出里提问后继续猜。
- 产物通过 `deliver` 回写（PR 链接 / 文件路径 / 分支名），不靠平台解析输出。
- 需要人确认的动作调用 `request_approval(action_type, body)`，等待结果；被否决时按否决原因调整或结束。

#### 验收条件（交互级）

##### 正常：飞书回复送入会话
- **GIVEN** 私聊收到"[需要你回答] T-231"
- **WHEN** 我在飞书回复"方案二"
- **THEN** 10 秒内线程出现我的消息与"已送入会话"，飞书收到"已送入 T-231 的会话"

##### 异常：回复非需要输入的消息
- **GIVEN** 私聊里有一条"[待拍板]"消息
- **WHEN** 我用文字回复它"改成出方案"
- **THEN** 机器人回复"该消息用 ✅/❌ 操作，修改请到面板：<链接>"，不执行

### S01: 飞书推送（补充）

- 分流卡就绪的推送使用"待拍板"模板；同一任务的重复推送（分流卡更新）在原消息下以回复形式追加，不发新消息。
- 一天内推送超过 30 条时，后续待拍板项合并为每小时一条"你有 N 项待拍板：<链接>"，避免刷屏。

#### 验收条件（交互级）

##### 异常：推送合并
- **GIVEN** 当日已推 30 条
- **WHEN** 第 31 条待拍板产生
- **THEN** 不立即推送，整点收到合并消息，面板收件箱不受影响

## 四、调度员与任务会话的 MCP 工具清单（M1）

| 工具 | 调用方 | 作用 |
|------|--------|------|
| `get_task(T-id)` | 任务会话 | 读上下文包、任务树、历史事件 |
| `report_progress(T-id, text)` | 任务会话 | 进展摘要 |
| `ask_user(T-id, question)` | 任务会话 | 需要输入，阻塞直到回复或超时 |
| `request_approval(T-id, action_type, body)` | 任务会话 | 生成审批，阻塞直到结果 |
| `deliver(T-id, artifacts[])` | 任务会话 | 产物回写 |
| `lookup_jira(key)` / `lookup_pr(repo, n)` | 调度员、任务会话 | 查证引用 |
| `list_tasks(filter)` | 调度员 | 找候选 |
| `propose_task(draft)` | 调度员 | 草案卡 |
| `ask_clarification(text, candidates[])` | 调度员 | 澄清气泡 |
